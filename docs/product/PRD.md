# PRD — Prompt Studio CN

- **状态**：Draft / Foundation
- **目标版本**：V1.0 Local Studio
- **当前实现**：V0.2 Prototype

## 1. 背景

AI 创作者通常把 Prompt、参考图、参数、模型、工作流和最终结果分散在聊天记录、笔记、图片目录、ComfyUI JSON 与浏览器收藏中。随着图片和视频模型增多，单纯保存 Prompt 已无法稳定复现结果，也难以沉淀个人创作方法。

Prompt Studio CN 需要提供一个本地优先的统一工作台，把这些碎片整理成结构化 Creation Asset。

## 2. 产品目标

### P0
1. 用户可以创建、编辑、保存和搜索 Creation Asset。
2. 用户可以通过模板和视觉参数构建图片/视频 Prompt。
3. 每个资产可以绑定效果图、参考图、模型配置和版本。
4. 大量媒体文件使用本地文件系统，元数据使用 SQLite，而不是 LocalStorage。
5. 用户可以导入/导出完整 Creation Pack。

### P1
6. 可视化模板编辑器：无需修改代码即可新增参数组和选项。
7. Workflow 数据模型与节点编辑器。
8. ComfyUI 本地 API 集成。
9. 同一资产针对不同模型保存 Model Profile / Prompt Variant。
10. 从输出案例 Fork 为新资产。

### P2
11. 可选在线分享页面。
12. 社区浏览、Fork、收藏、作者主页。
13. 多设备同步与团队空间。

## 3. 核心用户任务

### JTBD-01：从效果出发
当我看到一个喜欢的生成效果时，我希望知道它由哪些 Prompt、参数、模型和参考素材产生，并基于它快速修改。

### JTBD-02：参数化构建
当我不熟悉专业 Prompt 术语时，我希望通过中文选项和效果缩略图组合出高质量 Prompt。

### JTBD-03：沉淀工作流
当一套生成方法经过多次调试后，我希望把它保存为模板/工作流，而不是下次重新找聊天记录。

### JTBD-04：跨模型适配
当我从一个模型切换到另一个模型时，我希望保留同一创作意图，但切换对应的 Prompt Variant 和模型参数。

### JTBD-05：分享与 Fork
当我把方法发给别人时，我希望一次分享效果图、Prompt、参数、参考说明和 Workflow，而不是发十几个零散文件。

## 4. 核心对象

- **Creation Asset**：一个完整创作方法/案例的顶层对象。
- **Prompt Variant**：同一资产针对模态或模型的 Prompt 版本。
- **Template**：可参数化生成 Prompt 的结构定义。
- **Model Profile**：模型专属参数、能力与提示规则。
- **Media Asset**：封面、参考图、输出图、视频、音频。
- **Workflow**：节点、连接、输入输出和执行适配。
- **Creation Pack**：可导入导出的分享容器。

## 5. 功能需求

### FR-01 发现 / Gallery
- 网格展示效果图和视频封面。
- 可按模态、模板、模型、标签筛选。
- 点击进入 Asset Detail。
- Asset Detail 支持“载入 Builder”“Fork”。

### FR-02 Builder
- 图片、视频、3D、音频采用独立参数面板。
- 参数变化实时更新 Prompt Preview。
- 支持自由文本覆盖和锁定字段。
- 支持正向 Prompt、Negative Prompt、模型参数。
- 视频必须支持主体运动、镜头运动、时长、节奏、首尾状态、声音/对白等字段。

### FR-03 Template Editor
- 创建参数组、单选、多选、文本、数值、媒体引用等字段。
- 每个选项可绑定 Prompt Fragment、中文说明、缩略效果图和模型适配。
- 支持模板版本和导入导出。

### FR-04 Library
- 保存、复制、归档、删除、收藏。
- 全文搜索 Prompt、标题、说明和标签。
- 支持批量标签。
- 保存最近编辑和版本历史。

### FR-05 Media
- 媒体存本地文件系统，数据库只保存引用和元数据。
- 自动生成缩略图。
- 原文件不可因重新命名资产而丢失。
- 支持图片和视频预览。

### FR-06 Workflow
- 可保存节点和边。
- 节点可引用 Prompt、Model Profile、Media Input 和外部执行器。
- V0.4 首个外部执行器为 ComfyUI。

### FR-07 Share Pack
- 导出时包含 manifest、Prompt、参数、模板依赖、Workflow 和可选媒体。
- 导入前展示内容清单与冲突处理方式。
- 默认不打包 API Key、绝对本地路径或敏感配置。

### FR-08 Settings
- 数据目录、缓存目录、语言、默认模态。
- 外部集成地址和凭据使用安全存储。
- 备份/恢复。

## 6. 非功能需求

- **NFR-01 本地优先**：无账号也能使用核心功能。
- **NFR-02 隐私**：用户素材默认不上传。
- **NFR-03 可迁移**：核心数据具备稳定 Schema 和导出格式。
- **NFR-04 容量**：设计目标至少支持 10,000 个资产元数据与 TB 级媒体目录，而不把媒体写入数据库 Blob。
- **NFR-05 容错**：应用异常退出不能损坏已保存资产。
- **NFR-06 性能**：常规本地搜索与页面切换体感应接近即时；大图使用缩略图加载。
- **NFR-07 可扩展**：新增模型不需要修改核心资产模型。

## 7. V0.3 MVP 验收标准

- [ ] SQLite 数据库自动初始化与迁移。
- [ ] 用户可自定义数据目录。
- [ ] 可创建/编辑/删除 Creation Asset。
- [ ] 支持图片与视频两种正式 Builder。
- [ ] 支持至少一个用户自定义 Template。
- [ ] 媒体文件复制/引用到资产目录并生成缩略图。
- [ ] 搜索标题、标签和 Prompt。
- [ ] 支持 Creation Asset JSON 导入导出。
- [ ] V0.2 LocalStorage 数据提供一次性迁移方案。

## 8. 成功指标

V1.0 优先使用产品行为指标，而不是社区增长指标：
- 资产再次使用率
- 模板复用次数
- Fork 后修改并保存的比例
- 从 Gallery 到 Builder 的转化
- 工作流成功运行率
- 用户无需外部笔记即可复现历史结果的比例

## 9. 风险

- 多模态字段无限膨胀 → 使用共享 Core + modality extension。
- 不同模型 Prompt 语法差异 → Model Profile + Variant，不污染核心资产。
- 媒体目录移动导致引用失效 → 使用相对 Asset ID / managed storage。
- 过早社区化拖慢本地核心 → V1.0 前社区只做 Pack/Fork 基础。
